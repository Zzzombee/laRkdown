# 一次执行的项目升级

每个版本只下载一个 laRkdown-v<版本>.zip。ZIP 内 laRkdown/ 为个人科研目录，maintenance/ 为并列维护目录；豆包只打开 laRkdown/。升级技能、脚本和版本资料不进入科研指引。

## 默认升级流程

把新 ZIP 解压到原科研目录之外，然后执行一次：

```text
python <新解压目录>/maintenance/upgrade_larkdown.py --project <原科研目录> --apply
```

脚本默认读取同包相邻 laRkdown/ 和 maintenance/release/，不要求重复下载或手工指定版本。一次进程完成识别、文件核验、冲突判定、备份、应用及回执；已明确要求升级即直接执行，不必让模型先分析预览。成功输出版本与变更数量；完整计划和回执保存 .work/upgrades/last-report.json。冲突只返回数量和前五个必要定位，完整明细按需读取。

省略 --apply 为可选只读预览；追加 --verbose 才输出完整计划。--package <ZIP> 可显式读取统一 ZIP。--latest 下载并校验最新统一 ZIP，自带同版元数据，不再匹配第二个维护包。普通科研启动和日常操作不运行升级或发行校验。

## 历史与保护

支持清单中的 v0.1.0、v0.2.0～v0.2.5 及后续受支持版本。未修改的旧维护文件移出科研入口；AGENTS 用户增补三方合并，重叠或其他托管文件被修改时阻止整次应用。旧 README 只在匹配已发布原文哈希时替换。未知和私人文件不自动删除。

保留飞书文档登记、本机配置、原始资料、科研产物和多维表格基线。维护回执在 .work/upgrades/installed.json；无标记的干净科研目录可按精确哈希识别，无法可靠识别时停止，不猜版本。开发仓库和 product/ 源目录不能作为升级目标。

## 恢复

升级先备份并写事务日志，中断后执行：

```text
python <新解压目录>/maintenance/upgrade_larkdown.py --project <原科研目录> --recover
```

发现中断后的人工修改时停止，不覆盖。升级不访问飞书或重新初始化科研状态。完成后在豆包重新打开原科研目录。

## token 优先级

机器核验不交给模型逐文件解释，不在用户电脑运行开发测试、清单重建或全项目审计。正常路径短回执，冲突或失败才读取日志；保留必要的本地校验、冲突保护及恢复。
