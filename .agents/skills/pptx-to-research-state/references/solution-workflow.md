# 指定 RQ 的解决方案

只在用户明确要求为指定 RQ 生成方案时新建 SOL；初始化和普通 PPTX 更新不创建 SOL。目标 RQ 未指定时先澄清，不自行选择。既有 SOL 的维护限于请求及直接受影响的内容。

## 证据与路线拟合

读目标 RQ 全文、直接关联 OBS/CON/HYP 和该 RQ 已有 SOL。仅当路线取舍依赖论文定位或故事比较时读相关 PROJECT_STORY；涉及故事或机制、功能、工程能力主张时遵循项目的 story-policy.md。明确待解决的决策、已知事实、缺口和不能假定的参数。

先完整读取并执行 `../../literature-source-gate/SKILL.md`。它是发现来源、身份/正文核验、指标、例外、警示、证据标签和引文格式的唯一详细规则源；不在本工作流另列数据库或另设门槛。默认检索请求日前五年；超期的经典或不可替代来源仅按该政策的适用例外保留，记录理由及所需警示。用户明确指定的文献按该 skill 的指定来源模式处理。

先用已核验文献限定可行路线，再结合项目证据、用户指定方向、创新优先级、动物/模型和实验约束拟合方案。没有新偏好时沿用目标 RQ 的优先级。区分文献事实、项目事实、路线假设、拟议实验，以及直接支持、间接支持、合理性和推测。说明 prior art 已覆盖什么、本项目仍需证明什么和不能外推的体系差异；不为维持预设路线放宽来源门槛、增强证据或补造参数。

## 结构与路线保护

创建或结构性维护前，读取 `../../maintain-research-state/SKILL.md` 及其 schema；由它管理稳定编号、可见元数据、状态、RQ 回链和一次适度校验。使用飞书原生标题、段落和表格，元数据包含 solution_id、related_rq、status、date、core_route，不使用笔记属性或行尾锚点。飞书 block ID 仅作当前定位信息，结构修改后重新回读。

一个 SOL 只承载一个稳定核心路线并关联一个主 RQ；一个 RQ 可有多个 SOL。既有 core_route 仅在用户明确要求改变路线时修改；实质不同的模型、靶区、干预逻辑或功能目标新建 SOL。实施细节、剂量探索、对照和措辞可留在同一路线内；暂缓、否定、取代的路线保留原生文档和编号。创建 SOL 与目标 RQ 的真实飞书链接在同一批修改中完成。

## 成文与完成

完成科学结构和引用核验后，必须使用 academic-writing-editor 校订：优先项目 `.agents/skills/academic-writing-editor/SKILL.md`，其次当前技能目录中的同名技能。两者均缺失时停止最终 SOL 生成并报告路径，不用通用润色替代。

成文先给建议，再说明依据、竞争路线、分阶段实验、判定标准及证据边界。保留来源警示和不确定性。完成用户要求的 SOL、RQ 回链、适用检查及简短交付，不在中间计划处停止。
