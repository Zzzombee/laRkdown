# 原生科研记录结构

## 身份与存储

正式记录为飞书原生文档。逻辑 key：CURRENT_STATE（事实/结论/假设）、RESEARCH_QUESTIONS（问题/优先级）、PROJECT_STORY（目标故事）、SOL-###（指定 RQ 的路线）。登记仅保存 document_id、真实 URL、读取 revision_id 和当前条目映射，不存正文权威副本或凭证。

研究 ID 格式：OBS-###、CON-###、HYP-###、RQ-###、SOL-###，从 001 开始。研究 ID 出现在可见原生标题开头，例如 `<h2>OBS-001 — 条目标题</h2>`。不使用行尾锚点或笔记属性。平台 block ID 从最新 fetch 取得，可随结构变化而变化；研究 ID 永久稳定。废弃条目保留其编号、内容、状态及原因，禁止删除后复用。

日期、状态、证据等级、primary RQ 和 core_route 写成可见正文或原生表格。文档正文修改后更新其可见日期，编号和校验规则不随语言编辑改变。

## 条目

- OBS：直接观察或测量，保留系统、条件、对照、时间与 readout；未提供的关键参数标为缺失。解释不混入 OBS。
- CON：原生链接支持 OBS，写明证据等级（初步/中等/较强/充分）、支持边界、限制和必要替代解释。发表状态不自动提高等级，子主张分别定级。
- HYP：明确“未验证/假设”，链接所解释的 OBS 或目标 RQ，给可区分竞争解释的实验方向。
- RQ：问题、优先级、竞争解释和决定性缺口；已有方案时明确链接其 SOL。不把问题改写为预设路线的宣传。
- SOL：仅在用户明确指定 RQ 并要求方案时创建。一个 SOL 一个主 RQ；可见字段为 solution_id、related_rq、status、date、core_route。core_route 记录模型/体系、目标、干预逻辑和主要功能目的；只有明确授权才替换。RQ 必须显式链接该 SOL。

## 关系与链接

CON → 支持 OBS；HYP → 所解释 OBS/目标 RQ；SOL → 主 RQ 且 RQ → SOL。关系在正文以真实 `<a href="实际飞书URL#当前block_id">OBS-001</a>` 表达。未知目标只保留纯研究 ID 和待定位状态，不伪造 URL，也不将此状态当作关系已完成。

移动/替换标题后重新查询块 ID 并修复受影响引用。不能依赖自动反向链接。外部文献使用实际 DOI/期刊链接，并按 literature-source-gate 区分直接、间接、合理性、冲突与推测。

## 校验边界

校验器读取官方 fetch JSON/XML，检查稳定标题 ID 重复、关系缺失、CON 等级、HYP 标签、SOL 回链、已知块链接与遗留格式。局部 snapshot 不足以分配 ID 或执行全局审计。结构校验不决定科学真伪，不提高证据等级。

只读、拼写、日期和不改关系的正文修改不做结构审计。小批次改变做定向检查；跨文档迁移/明确全局审计提供全部登记快照后检查一次。新增错误由当前任务修复，既有无关问题单独报告。
